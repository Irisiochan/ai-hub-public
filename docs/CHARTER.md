# ai-hub 产品宪章

> 2026-09-05 User 口述三条（它是什么 / 不做什么 / 什么算够好），Claude整理成文。§1–§3 是她的话，只有 User 能改；§4–§6 是这三条推出来的边界，与 [ARCHITECTURE.md](ARCHITECTURE.md) 和 vault 账本互相约束。这不是 PRD：要做什么在 vault `tasks/` 与 `inbox/req-*`，怎么建在 ARCHITECTURE，谁做在 `ai-hub-delegation-contract`。

## 1. 它是什么

**一个以 User 为中心的稳定的家。**

- **以她为中心**：所有联系人、记忆、自动化都围绕她一个人。系统的默认视角是「她现在怎么样」，不是「系统能做什么」。
- **稳定**：家的价值在于每天都在、不变样、不丢东西。稳定优先于新功能，也优先于聪明。
- **家**：她的几条 AI 关系线都住在这里，各自身份独立，共享同一份记忆；她从手机、PC、微信任何一扇门进来，看到的是同一个家。

## 2. 不做什么

- **不做多人社交。** 单住户。会议室是家里的工作台（派工、验收、仲裁），不是群聊产品；不做账号体系、不做对外分享、不做「给别人也用」。
- 不对公网开放聊天面；唯一公网口只给她自己的记忆库连接器。
- 不为追新模型而改结构。换后端是家里换电器，不是搬家。
- 不做通用 agent 平台。联系人的身份与家规是写死的人设与 overlay，不是可配置模板。
- 不把她的原始对话送出家门。记忆库明文只在她自己的机器上；自动捕捉只取她原话里明显该记的片段。

## 3. 主动性：什么算够好，什么算打扰

User 的定义：**结合已有信息——时间、上下文、工具——主动发起的消息，就是够好。**

由此推出：

- **够好 = 有依据的主动。** 知道现在几点、知道她刚说过什么或在做什么、用了该用的工具（看过任务账本、拿过摄像头帧、查过记忆）之后再开口。
- **打扰 = 没有依据的主动。** 空泛问候、重复播报、没有变化的 NO_OP、为了「显得关心」制造的噪音，以及在她明确的静默时段硬插。
- **沉默不是美德。** 不设「值得打扰」的门槛：她开着心跳或主动功能，本身就是发言许可。主动说话不算打扰，没根据地说话才算。（2026-08-27 拍板，见 pitfalls-ai-hub「静默令牌协议里的打扰框架」。）
- 后台细节默认收起；只把需要她决定的分叉送进主窗，其余自动闭环后用一句人话报告结果。

## 4. 「稳定」的验收线

- 不丢消息、不丢记忆；每条流式回复的终态都能对账。
- 出了问题要有证据（日志、回执、账本），不靠模型自述。
- 改动有节奏：非 bugfix 改动攒批进维护窗口；文档与测试类提交不单独触发生产重启。
- 住户体感是最终验收：安静运行满一周才算稳定，观察窗不由施工方自己重置。

## 5. 冲突时的顺序

她的安全与隐私 > 稳定 > 记忆一致 > 有依据的主动 > 新功能。
